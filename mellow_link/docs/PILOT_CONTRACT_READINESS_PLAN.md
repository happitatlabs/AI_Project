# Pilot Contract Readiness Plan

`mellow_link`의 "파일럿 계약 가능" 상태를 완료로 끌어올리기 위한 기준, 체크리스트, 2주 구현 백로그, Jira 티켓 초안이다.

## 현재 상태 메모

기준일: 2026-03-25

현재 이미 반영된 항목:

- 프로젝트 기반 3화면 UX
  - 새 프로젝트
  - 분석 워크스페이스
  - 결과 패키지
- 프로젝트별 자산 메타 관리와 재분석 흐름
- 결과 패키지의 `진단 / 설계안 / 전환 초안` 구조
- 익명화 MVP 공통 계층 도입
- safe bundle 기반 분석 실행선 고정

현재 이 문서는 남은 파일럿 계약 준비 항목을 보는 용도로 해석한다.

## 목적

- 현재 상태를 `데모 가능`에서 `유료 파일럿 제안 및 수행 가능` 단계로 올린다.
- 기준은 아래 4가지를 충족하는 것이다.
  - 재현 가능한 결과 패키지
  - 프로젝트 단위 자산 영속 관리
  - 보안/설치/운영 설명 가능
  - 제안서 및 표준 산출물 송부 가능

## 파일럿 계약 체크리스트

| 구분 | 체크 항목 | 완료 기준 |
|---|---|---|
| 상품 정의 | 파일럿 범위 정의 | 단일 기능/단일 화면/단일 업무 흐름 기준으로 범위를 문서화 |
| 상품 정의 | 비지원 범위 명시 | 전체 시스템 전환, 자동 코드 치환, 운영 배포는 제외라고 명시 |
| 상품 정의 | 고객 준비물 정의 | 소스, 화면, SQL, DB 스키마, 프레임워크 정보 제출 목록 확정 |
| 산출물 | 표준 산출물 명세 | 진단서, 설계안, 전환 초안, 부록의 목차와 형식 고정 |
| 산출물 | 1페이지 요약본 | 임원/영업 설명용 요약 자동 생성 또는 템플릿 확보 |
| 실행 | 프로젝트 생성 플로우 | 새 프로젝트 생성부터 결과 패키지 다운로드까지 데모 가능 |
| 실행 | 재분석 플로우 | 추가 자료 업로드 후 같은 프로젝트에서 재분석 가능 |
| 데이터 | 자산 영속 저장 | 업로드 파일과 메타데이터를 프로젝트 단위로 재열람 가능 |
| 데이터 | 결과 재현성 | 입력 자산 목록, 실행 시각, 분석 버전, run_id가 결과에 포함 |
| 데이터 | 익명화 경계 설명 | canonical/internal/public export 경계를 문서와 데모에서 설명 가능 |
| 보안 | 접근 통제 | 프로젝트 소유권, 관리자 범위, 인증 방식 설명 가능 |
| 보안 | 데이터 정책 | 저장 위치, 보관 기간, 삭제 방식, 반출 여부 문서화 |
| 설치 | 설치 가이드 | 1대 설치 기준 절차, 의존성, 소요 시간, 장애 대응 문서화 |
| 영업 | 파일럿 제안서 | 기간, 범위, 산출물, 고객 준비사항, 제외사항 포함 |
| 영업 | 성공 기준 합의 | 데모 성공, 결과 설명 가능, 후속 설계 논의 가능 등 KPI 합의 |
| 계약 | 파일럿 종료 기준 | 납품물 전달, 결과 리뷰 1회, 후속 계약 제안까지 정의 |

## 티켓 상세

### MLP-101 프로젝트 자산 영속 저장 설계/구현

- 설명: 현재 임시 업로드 중심 흐름을 프로젝트 단위 영속 저장으로 전환한다.
- 대상: 업로드 파일 원본, 메타데이터, 프로젝트 연계.
- 완료조건:
  - 프로젝트별 업로드 파일이 서버 재시작 후에도 남는다.
  - 파일명, 크기, 업로드 시각, 프로젝트 ID를 조회할 수 있다.
  - 임시 저장만으로 끝나지 않고 프로젝트 자산으로 승격된다.

### MLP-102 프로젝트 자산 목록/재열람 UI 추가

- 설명: 워크스페이스에서 업로드 자산을 다시 볼 수 있게 한다.
- 완료조건:
  - 프로젝트 상세 화면에서 자산 목록이 보인다.
  - 각 자산의 기본 메타데이터가 표시된다.
  - 최소한 다운로드 또는 원문 보기 중 하나가 가능하다.

### MLP-103 결과 패키지 provenance 추가

- 설명: 결과가 언제 어떤 입력과 버전으로 생성됐는지 패키지에 남긴다.
- 완료조건:
  - 결과 패키지에 `run_id`, 생성 시각, 입력 자산 목록이 포함된다.
  - 분석 버전 또는 룰 버전이 포함된다.
  - Markdown/PDF/HTML 모두 같은 provenance를 보여준다.

### MLP-104 재분석 플로우 추가

- 설명: 추가 자료 업로드 후 같은 프로젝트에서 다시 분석할 수 있게 한다.
- 완료조건:
  - 프로젝트 상세에서 `추가 자료 업로드`와 `재분석`이 가능하다.
  - 이전 실행 이력과 최신 실행이 구분된다.
  - 결과 패키지에서 최신 실행 기준이 명확하다.

### MLP-105 파일럿 범위/한계 문구 고정

- 설명: 과대 약속을 막기 위해 범위를 UI와 산출물에 고정 문구로 넣는다.
- 완료조건:
  - 프로젝트 생성 화면에 지원 범위가 표시된다.
  - 결과 패키지에 비지원 범위가 표시된다.
  - `단일 기능/단일 화면 V0` 메시지가 일관되다.

### MLP-106 1페이지 요약본 생성 추가

- 설명: 임원/영업 설명용 요약본을 결과 패키지 상단에 추가한다.
- 완료조건:
  - 핵심 결론, 현대화 방향, 주요 리스크, 다음 단계가 1페이지 수준으로 나온다.
  - 상세 산출물과 분리된 요약 섹션이 존재한다.

### MLP-107 보안/데이터 취급 문서 작성

- 설명: 고객 질문 대응용 운영/보안 설명 문서를 만든다.
- 완료조건:
  - 데이터 저장 위치, 보관 기간, 삭제 방식이 문서화된다.
  - 관리자 접근 범위와 인증 방식이 문서화된다.
  - 파일럿 제안서에 첨부 가능한 1장 문서가 나온다.

### MLP-108 설치형 운영 가이드 작성

- 설명: SI/컨설팅 고객 대상 설치 절차를 정리한다.
- 완료조건:
  - 설치 순서, 필수 의존성, 예상 설치 시간, 장애 대응 절차가 문서화된다.
  - 신규 환경에서 따라할 수 있는 체크리스트가 있다.

### MLP-109 표준 산출물 템플릿 고정

- 설명: 결과 패키지를 납품물 형태로 고정한다.
- 완료조건:
  - 진단서, 설계안, 전환 초안, 부록의 표준 목차가 확정된다.
  - PDF로 납품 가능한 형태가 정리된다.

### MLP-110 template_key 처리 정리

- 설명: 현재 저장만 되고 실효성이 약한 템플릿 처리를 정리한다.
- 완료조건:
  - 실제로 동작 차별화를 붙이거나, 없으면 UI에서 숨긴다.
  - 사용자에게 오해를 주는 옵션이 남지 않는다.

### MLP-111 파일럿 KPI/성공 기준 문서화

- 설명: 계약 후 성공 판정 기준을 고정한다.
- 완료조건:
  - 데모 성공, 결과 설명 가능, 후속 설계 논의 가능 등 KPI가 정의된다.
  - 제안서와 결과 보고서에 같은 기준이 반영된다.

### MLP-112 파일럿 제안서 초안 작성

- 설명: 바로 보낼 수 있는 상업 문서를 만든다.
- 완료조건:
  - 범위, 기간, 고객 준비물, 산출물, 제외 항목, 성공 기준이 포함된다.
  - 1차 제안용 문안이 완성된다.

### MLP-113 E2E 데모 리허설 및 체크리스트 검증

- 설명: 실제 파일럿 영업 시나리오를 처음부터 끝까지 점검한다.
- 완료조건:
  - `새 프로젝트 -> 업로드 -> 분석 워크스페이스 -> 결과 패키지 -> PDF 저장`이 끊김 없이 시연된다.
  - 10분 내 데모 가능하다.
  - 발견된 blocker가 없거나 별도 버그 티켓으로 분리된다.
