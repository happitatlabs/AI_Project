# 문서 기반 AI 실행 파이프라인 운영 규칙

버전: v1.0  
용도: 에이전트 실행 기준 문서  
적용 대상: 문서 초안 생성 -> 에이전트 실행 -> 결과 반영 -> 불필요 항목 제거 루프 전체

---

## 1. 목적

이 문서는 문서 기반으로 작업을 생성, 실행, 수정하는 반복 구조에서 에이전트가 무엇을 기준으로 실행해야 하는지, 그리고 어떤 문서만 현재 유효한 실행 기준으로 취급해야 하는지를 고정하기 위한 운영 규칙이다.

핵심 목표는 다음과 같다.

- 문서 초안과 실행 기준 문서를 구분한다.
- 에이전트가 참고할 문서를 명확히 제한한다.
- 실행 후 결과를 다시 문서에 반영하되, 중복, 충돌, 불필요 누적을 막는다.
- 사람은 수정자가 아니라 판단자로 남는다.

## 2. 기본 원칙

### 2.1 역할 분리 원칙

- 사람(오너)
  - 초안 방향 제시
  - 결과 검토
  - 유지 / 수정 / 삭제 결정
- 문서 생성 AI
  - 초안 문서 작성
  - 구조화
  - 실행 기준 문서 정리
- 실행 에이전트
  - 현재 유효한 실행 기준 문서를 바탕으로 실제 코드/구조 변경 수행
  - 결과 반영용 변경 요약 생성

실행 전에 반드시 문서 기준이 있어야 하며, 에이전트는 대화 전체가 아니라 명시된 실행 기준 문서를 우선 참조한다.

## 3. 문서 상태 정의

모든 문서는 아래 3가지 상태 중 하나를 가져야 한다.

### 3.1 Draft

정의:

- 아이디어 정리용 초안 문서
- 자유롭게 생성 가능
- 실험적 가정 포함 가능
- 실행 기준으로 바로 사용하지 않음

특징:

- 버려질 수 있음
- 충돌 가능
- 중복 가능

### 3.2 Contract

정의:

- 에이전트가 실제 실행 시 참조하는 공식 실행 기준 문서
- 현재 작업 범위, 완료 조건, 금지 사항, 수정 대상이 명확해야 함

특징:

- 같은 작업 범위에서 가장 우선하는 문서
- 모호한 표현 금지
- 충돌 금지
- 실행 가능한 형태여야 함

### 3.3 Locked

정의:

- 실행 및 검토를 거쳐 현재 유효성이 확인된 확정 기준 문서
- 이후 다른 작업에서도 참조 가능한 기준 문서

특징:

- 변경 시 영향 검토 필요
- 쉽게 덮어쓰지 않음
- 장기 기준으로 사용

## 4. 전체 작업 루프

다음 순서를 기본 루프로 사용한다.

```text
1. 초안 생성 (Draft)
2. 실행 기준 확정 (Contract)
3. 에이전트 실행 (Build)
4. 결과 반영 (Reflect)
5. 검토 및 분류 (Filter)
6. 기준 문서 갱신 (Lock)
```

---

## 5. 단계별 운영 규칙

### 5.1 초안 생성 (Draft)

목적:

- 아이디어를 빠르게 문서화
- 방향성, 구조, 선택지를 정리

허용:

- 가정
- 비교안
- 탐색성 표현
- 실험적 구조

금지:

- 이 단계 문서를 바로 실행 기준으로 사용
- 중복 초안을 장기간 방치

출력 예시:

- 기능 초안
- 설계 아이디어
- 패턴 후보
- 문서 구조 제안

---

### 5.2 실행 기준 확정 (Contract)

목적:

- Draft를 에이전트가 실행 가능한 형태로 정제
- 현재 작업의 공식 기준 문서를 1개로 고정

필수 포함 항목:

- 작업 목표
- 현재 상태
- 수정 대상
- 완료 조건
- 금지 사항
- 산출물 형태
- 테스트 또는 검증 기준

원칙:

- Contract 문서는 가능한 한 작업 단위당 1개를 유지한다.
- 여러 문서를 둘 경우, 우선순위를 명시해야 한다.
- 에이전트는 Contract 문서 없이는 실행하지 않는다.
- Contract 문서가 없으면 실행 금지다.

---

### 5.3 에이전트 실행 (Build)

목적:

- Contract 기준으로 실제 변경 수행

에이전트 실행 규칙:

- Draft가 아니라 Contract를 기준으로 작업한다.
- 대화 중 임의 문장을 새 기준으로 채택하지 않는다.
- 지정된 수정 범위를 넘지 않는다.
- 모호한 경우 임의 확장보다 보수적으로 적용한다.
- 결과물에는 변경 파일, 변경 요약, 검증 결과를 남긴다.

에이전트 출력 최소 항목:

- 변경 파일 목록
- 핵심 변경 사항
- 테스트/검증 여부
- 잔여 이슈
- 문서 업데이트 필요 사항

---

### 5.4 결과 반영 (Reflect)

목적:

- 실행 결과를 문서에 다시 반영하여 기준과 실제 상태를 맞춘다.

반영 대상:

- 완료된 사항
- 미완료 항목
- 보류 항목
- 새로 드러난 제약
- 삭제 후보

원칙:

- 실행 후 문서를 업데이트하지 않으면 기준이 곧바로 오염된다.
- 결과 반영 문서는 Draft가 아니라 상태 갱신 문서 또는 Contract 후속 문서로 다룬다.
- `rebuild_assistant` 관련 실행 후에는 [`REBUILD_ASSISTANT_RESULT_STATUS_2026-03-28.md`](/C:/Users/Hyein/ClaudeAI/AI_Project/mellow_link/docs/REBUILD_ASSISTANT_RESULT_STATUS_2026-03-28.md)를 반드시 업데이트한다.

---

### 5.5 검토 및 분류 (Filter)

목적:

- 실행 후 문서와 구조를 유지 / 수정 / 삭제로 정리

분류 기준:

- KEEP: 계속 유지할 가치가 있는 항목
- MODIFY: 기준은 맞지만 표현/범위 보정이 필요한 항목
- DELETE: 더 이상 필요 없거나 충돌, 중복, 무효인 항목

오너 역할:

- 세부 구현보다 이 분류 판단을 우선한다.

---

### 5.6 기준 문서 갱신 (Lock)

목적:

- 이번 실행과 검토를 거친 뒤, 현재 유효한 기준 문서를 다시 확정한다.

원칙:

- 살아남은 규칙만 Locked 문서에 반영한다.
- Draft 내용 전체를 Locked로 올리지 않는다.
- 검증되지 않은 가정은 Locked에 넣지 않는다.

## 6. 문서 생성 조건

새 문서는 아래 중 하나를 만족할 때만 만든다.

### 생성 허용 조건

1. 이 문서가 있어야 에이전트가 작업을 정확히 수행할 수 있다.
2. 이 문서가 없으면 결과가 흔들리거나 기준이 충돌한다.
3. 실행 결과를 반영하기 위해 상태 갱신이 필요하다.
4. 기존 문서가 너무 커져 역할 분리가 필요하다.

### 생성 금지 조건

1. 같은 내용을 다른 말로 반복하는 문서
2. 실행과 연결되지 않는 정리 문서
3. 이미 Locked 문서에 있는 내용을 중복하는 문서
4. 현재 범위 밖 미래 아이디어만 모아둔 문서

---

## 7. 삭제 규칙

문서 삭제는 감이 아니라 아래 기준으로 수행한다.

### 7.1 실행 불가 문서

- 에이전트가 이 문서만 보고 작업할 수 없음
- 목표, 범위, 완료 조건이 없음

-> 삭제 또는 Draft로 강등

### 7.2 중복 문서

- 역할이 같은 문서가 2개 이상 존재
- 실제 기준이 어느 문서인지 모호함

-> 하나로 통합하고 나머지는 삭제

### 7.3 결과 영향 없음

- 문서가 없어도 결과가 동일
- 실제 실행/판단에 영향을 주지 않음

-> 삭제

### 7.4 오래된 기준

- 이미 새로운 Contract 또는 Locked 문서가 있음
- 과거 기준으로서만 의미가 있음

-> archive 또는 삭제

## 8. 에이전트 적용 규칙

에이전트는 아래 규칙을 기본 행동 규칙으로 사용한다.

### 8.1 입력 우선순위

```text
Locked > Contract > Draft > 대화 임시 문장
```

설명:

- Locked는 장기 기준
- Contract는 현재 작업 기준
- Draft는 참고용 아이디어
- 대화 임시 문장은 기준 문서에 반영되기 전까지 공식 기준이 아님

### 8.2 실행 금지 상황

다음 중 하나면 실행 보류 또는 축소 적용한다.

- Contract 문서가 없음
- Contract끼리 충돌함
- 수정 범위가 명확하지 않음
- 완료 조건이 없음
- 금지 사항이 없음
- 기존 Locked 문서와 정면 충돌함

위 조건 중 `Contract 문서가 없음`은 축소 적용이 아니라 기본적으로 실행 금지로 해석한다.

### 8.3 변경 범위 원칙

- 요구된 범위 바깥의 확장 구현 금지
- “좋아 보여서” 추가 금지
- 임의 구조 확대 금지
- 실행 후 기준 문서와 실제 상태가 어긋나면 반드시 보고

## 9. 권장 문서 구조 세트

프로젝트 전체 문서 체계는 아래 3종을 기본으로 한다.

### 9.1 기준 문서

용도:

- 장기 규칙
- 설계 원칙
- 패턴 정의
- 제품 방향

상태 권장:

- Locked

### 9.2 실행 문서

용도:

- 이번 작업 범위
- Codex/에이전트용 실행 기준
- 완료 조건 / 금지 사항 / 테스트 조건

상태 권장:

- Contract

### 9.3 결과 문서

용도:

- 실행 결과 요약
- 변경 내용
- 남은 이슈
- 다음 작업 연결

상태 권장:

- Reflect 후 필요시 Locked 일부 반영

## 10. 최소 운영 체크리스트

작업 시작 전:

- [ ] 이번 작업의 Contract 문서가 존재하는가
- [ ] 수정 범위가 명확한가
- [ ] 완료 조건이 적혀 있는가
- [ ] 금지 사항이 적혀 있는가

에이전트 실행 후:

- [ ] 변경 파일 목록이 남았는가
- [ ] 검증 결과가 남았는가
- [ ] 문서 상태 갱신이 되었는가
- [ ] 삭제 후보가 식별되었는가

라운드 종료 시:

- [ ] 이번 라운드에서 살아남은 기준이 무엇인지 명확한가
- [ ] Draft / Contract / Locked가 섞여 있지 않은가
- [ ] 중복 문서가 정리되었는가
