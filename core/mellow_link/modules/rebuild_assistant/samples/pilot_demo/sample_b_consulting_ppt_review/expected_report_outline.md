# 기대 보고서 개요

## 1. 한 줄 결론

분산된 업무 접수/처리 흐름은 상태 기준과 처리 이력 관리가 약하므로, 상태 표준화와 공통 관리 체계를 먼저 구축한 뒤 통합 접수/처리 포털로 단계 확장하는 것이 적절하다.

## 2. 입력 자료 요약

- `slides.md`는 업무 접수/처리 프로세스 개선 검토를 12장 흐름으로 제시한다.
- 자료는 배경, 현황, 문제, 사용자/운영 이슈, 데이터/연계 이슈, 개선 방향, 선택지 비교, 권장안, 추진 계획, 리스크, 기대 효과로 구성되어 있다.
- `sample_b_consulting_ppt_review.pptx`는 동일 내용을 업로드 가능한 프레젠테이션 형식으로 담고 있다.

## 3. 현행 구조 / 업무 흐름

- 요청 접수는 메일, 엑셀, 게시판, 메신저에 분산되어 있다.
- 담당자는 개인 목록이나 도구별 댓글로 처리 상황을 관리한다.
- 긴급 요청은 비공식 채널에서 먼저 처리되고 나중에 목록에 반영된다.
- 보고용 현황은 담당자가 별도로 취합해 재작성한다.
- 담당자 변경, 지연 사유, 사용자 확인 결과가 일관된 이력으로 남지 않는다.

## 4. 핵심 문제

- 접수, 검토, 처리, 완료, 반려 상태 정의가 부서별로 다르다.
- 요청 우선순위와 처리 기한이 명확히 기록되지 않아 지연 원인 파악이 어렵다.
- 동일 요청 여부, 담당자 변경, 반려 사유 확인이 수작업에 의존한다.
- 데이터 항목과 기준일 정의가 약해 대시보드와 보고 자동화가 어렵다.
- 기존 도구 간 연계 범위가 정리되지 않아 통합 개선의 선후관계가 불명확하다.

## 5. 개선 선택지

- A안: 기존 도구 유지 + 양식과 상태값 정리
  - 빠르게 적용할 수 있지만 이력 추적과 보고 자동화에는 한계가 있다.
- B안: 접수/처리 표준 프로세스 수립 + 공통 관리 목록 운영
  - 상태 기준과 필수 데이터 항목을 고정해 단기 안정화와 중기 확장의 기반을 만든다.
- C안: 통합 접수/처리 포털 구축 + 대시보드와 알림 연계
  - 운영 개선 효과는 가장 크지만 업무 기준, 데이터 정비, 전환 계획이 선행되어야 한다.

## 6. 권장안

B안을 먼저 추진해 요청 유형, 상태 정의, 필수 입력 항목, 담당자 변경 이력, 지연 사유 기준을 고정한 뒤 C안을 단계적으로 추진한다. A안은 단기 보완책으로만 사용하고 최종 목표는 통합 접수/처리 흐름과 현황 대시보드로 둔다.

## 7. 리스크와 검토 필요 사항

- 부서별 운영 방식 차이를 충분히 반영하지 않으면 표준 프로세스가 형식화될 수 있다.
- 기존 도구를 급하게 중단하면 처리 누락이나 문의 증가가 발생할 수 있다.
- 입력 항목이 많으면 현장 사용성이 떨어질 수 있다.
- 담당자 변경 이력과 지연 사유 입력이 정착되지 않으면 추적성이 개선되지 않는다.
- 권한 범위, 알림 채널, 기존 자료 보존 기준을 사전에 정해야 한다.

## 8. 단계별 실행 준비 계획

1. 요청 유형, 상태 코드, 처리 책임 기준을 정리한다.
2. 기존 요청 목록을 정비하고 필수 항목 누락 현황을 확인한다.
3. 공통 관리 목록과 담당자 변경 이력 구조를 설계한다.
4. 알림, 지연 기준, 완료 확인 절차를 정의한다.
5. 대표 부서와 대표 요청 유형으로 파일럿 운영을 수행한다.
6. 파일럿 결과를 바탕으로 통합 접수/처리 포털과 대시보드 적용 범위를 확정한다.

## 9. 분석 근거와 provenance

- 현황 근거: `slides.md` 2~3장
- 문제 근거: `slides.md` 4~6장
- 개선 방향 근거: `slides.md` 7장
- 선택지와 권장안 근거: `slides.md` 8~9장
- 실행 계획과 리스크 근거: `slides.md` 10~12장
