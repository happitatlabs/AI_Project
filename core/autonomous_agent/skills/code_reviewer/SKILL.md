# SKILL: code_reviewer

## name
code_reviewer

## description
워크스페이스 내 Python 코드 파일(.py)을 탐색하고, 각 파일의 함수/클래스 구조와 규모를 분석하여 판단 기반 리뷰 보고서를 생성한다. 실행하거나 수정하지 않고 읽기만 한다.

## when_to_use
- 코드 구조를 파악해야 할 때
- "코드 리뷰", "코드 분석", "함수 목록" 키워드가 목표에 포함될 때
- .py 파일이 워크스페이스에 존재할 때

## input
- workspace 경로 (기본: 현재 디렉토리)
- 대상 확장자: .py

## output
- code_reviewer_YYYYMMDD_HHMMSS.md (리뷰 보고서)

## output_format
보고서는 다음 5개 섹션을 반드시 포함한다. 단순 나열 금지 — 각 섹션에 해석/판단 문장 필수.

### 요약
총 .py 파일 수, 전체 라인 수, 평균 파일 규모를 한 문단으로 서술.
"이 코드베이스의 규모와 구조화 수준"에 대한 판단 포함.

### 주요 발견
가장 큰 파일, 함수가 가장 많은 파일, 클래스 구조 존재 여부를 해석.
단순 목록이 아닌 "무엇이 특이한가" 중심으로 기술.

### 분석
코드 구조 품질 평가:
- 파일당 평균 함수 수 해석 (적정: 5~10개)
- 클래스 기반 설계 여부 판단
- 모듈 간 역할 분리 수준 평가

### 문제점
**최소 2개 이상 필수.** 조건 미충족 시 코드 품질 관찰로 보충.
- 과도하게 큰 파일 (300줄 초과)
- 함수 수 과다 파일 (15개 초과)
- 클래스 미사용 (함수형 구성)
- 테스트 파일 혼재 여부
- docstring·타입힌트 미적용 (구조적 관찰)

### 제안
**최소 3개 이상 필수.** [높음/중간/낮음] 우선순위 + 구체적 액션.
- 분리 대상 파일 명시 (파일명 포함)
- docstring 추가 항상 포함
- 타입 힌트 적용 항상 포함
- 테스트 분리 또는 커버리지 권장

## steps
1. scan_code_files: .py 파일 목록 수집
2. extract_structure: 각 파일의 def/class 이름과 라인 수 추출 (AST 없이 grep 방식)
3. write_review: 결과를 Markdown으로 저장
