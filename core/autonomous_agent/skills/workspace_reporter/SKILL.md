# SKILL: workspace_reporter

## name
workspace_reporter

## description
워크스페이스 전체 파일 구조를 스캔하고, 파일 수/크기/유형 분포를 종합 분석하여 Markdown 상태 보고서를 생성한다. 다른 리포트의 기준점이 되는 종합 보고서를 담당한다.

## when_to_use
- 현재 워크스페이스 상태를 파악해야 할 때
- 정기 점검 보고서가 필요할 때
- 구조/운영/유지보수/확장성까지 한 번에 보는 종합 판단이 필요할 때
- "분석", "보고서", "현황", "상태 확인" 키워드가 목표에 포함될 때

## input
- workspace 경로 (기본: 현재 디렉토리)

## output
- workspace_reporter_YYYYMMDD_HHMMSS.md (워크스페이스 루트에 저장)

## output_format
보고서는 다음 5개 섹션을 반드시 포함한다. 단순 나열 금지 — 각 섹션에 해석/판단 문장 필수.

### 요약
전체 파일 수, 디렉토리 수, 총 크기, 지배적 확장자를 한 문단으로 서술.
숫자만 나열하지 말고 "어떤 프로젝트인지"를 판단하는 문장 포함.

### 주요 발견
상위 확장자 분포, 비율 기반 특징을 해석 문장으로 기술.
단순 목록이 아닌 "왜 이 분포가 중요한지" 포함.

### 분석
**3개 차원 필수:**
1. 현재 구조의 의미 — 분포 해석 + 구조적 특성 판단
2. 시간에 따른 변화 예상 — 에이전트 실행 횟수 증가 시 어떻게 변하는지
3. 이대로 두면 — 방치 시 어떤 문제로 이어지는지

### 문제점
**최소 3개 이상 필수.** 각 문제는 서로 다른 카테고리여야 함.
카테고리: [구조] / [운영] / [유지보수] / [확장성]
- 단순 관찰 금지 — 반드시 "왜 문제인지" 이유 포함
- 문제 접두어([구조], [운영] 등) 명시

### 제안
**최소 3개 이상 필수.** 모든 제안은 서로 중복 금지.
형식: [우선순위] 무엇을 → 어떻게 → 왜(기대 효과)
- 대상, 수행 액션, 기대 효과를 모두 포함
- 동일 대상 중복 금지
예: [높음] 로그 파일 2개를 → `logs/` 생성 후 이동 → 운영 파일과 소스 분리

## steps
1. scan_workspace: 파일 목록과 크기 수집
2. classify_by_extension: 확장자별로 그룹화
3. write_report: 결과를 Markdown 파일로 저장

safe
