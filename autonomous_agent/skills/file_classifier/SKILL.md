# SKILL: file_classifier

## name
file_classifier

## description
워크스페이스의 파일을 확장자와 유형별로 분류하고, 디렉토리 경계와 배치 기준 중심의 구조 분류 보고서를 생성한다. 종합 상태 평가는 제외하고 구조 분류에만 집중한다.

## when_to_use
- 파일 정리가 필요할 때
- 코드/문서/설정/기타의 구조 경계를 명확히 보고 싶을 때
- "분류", "정리", "파일 종류", "organize" 키워드가 목표에 포함될 때
- 파일 수가 많아 구조 파악이 어려울 때

## input
- workspace 경로 (기본: 현재 디렉토리)

## output
- file_classifier_YYYYMMDD_HHMMSS.md (분류 보고서)

## output_format
보고서는 다음 5개 섹션을 반드시 포함한다. 단순 나열 금지 — 각 섹션에 해석/판단 문장 필수.

### 요약
전체 파일 수, 카테고리 수, 지배적 카테고리를 한 문단으로 서술.
"현재 파일 구조의 혼재 정도"에 대한 판단 포함.

### 주요 발견
카테고리별 비율과 특이점 해석.
어떤 카테고리가 비대하거나 불균형한지 "왜 문제인지" 포함하여 기술.

### 분석
파일 분포가 프로젝트 관리 상태에 대해 무엇을 의미하는지 판단:
- 코드/문서/데이터/설정/기타 비율 해석
- 루트 디렉토리 혼재 여부 평가
- 정리 필요 긴급도 판단 (높음/중간/낮음)
- 운영/행동 리포트와 중복되는 종합 평가는 제외하고 구조 경계 판단에 집중

### 문제점
**최소 2개 이상 필수.** 조건 미충족 시 구조적 관찰로 보충.
- 루트에 혼재된 이질적 파일
- 분류 불가 "기타" 파일 과다
- 설정 파일 분산 배치

### 제안
**최소 3개 이상 필수.** [높음/중간/낮음] 우선순위 + 구체적 액션.
- 이동 대상: 파일 유형 → 권장 디렉토리 (구체적 파일 수 명시)
- 구조 기준 문서화 포함
- 삭제 후보는 구조 분류와 직접 관련된 임시/중복 파일로 제한

## steps
1. scan_workspace: 전체 파일 목록 수집
2. group_by_type: 확장자별 그룹화 (코드/문서/데이터/기타)
3. suggest_actions: 각 그룹에 대한 정리 제안 생성
4. write_classification: 결과를 Markdown으로 저장

safe
